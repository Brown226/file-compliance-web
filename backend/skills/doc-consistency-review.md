# 文档一致性审查 Skill

当用户要求对一组相关文档做「一致性核查 / 不一致对照 / 交叉审查 / 找矛盾」（如系统文件与 PSAR/设计报告、正文与附表、图纸与清单、新旧版本之外的跨文档核对）时，按本流程执行。

> 本 Skill 与办公模板 `office_doc_consistency_review` 配套：模板为注入 system prompt 的可执行流程（模型实际执行依据），本 Skill 为完整细则与报告模板参考。

## 触发场景
- 「审查这几个文档有什么不一致性」「对照 XX 与 XX 找差异」「核查文件一致性」「交叉比对」等
- 典型：系统文件 ↔ 设计报告正文 ↔ 附表数据表；正文描述 ↔ 设备一览表

## 执行流程

### 第一步：文档定位与角色判定
1. 列出全部输入文档，判定每份的角色：
   - **基准描述**：正文/系统文件（完整设计描述，含章节结构）
   - **数据表**：附表/设备清单/一览表（位号+参数为主）
   - **修订记录**：修订说明（声明了修改内容与方向，是重要的交叉验证依据）
2. 确定审查对象（哪个系统/章节）与锚点关系：正文引用哪些表、表与正文的对应方式。

### 第二步：文本与表格提取
- 优先用 `extract_text` / `extract_tables` 提取文本与表格
- .doc 老格式（Word 97-2003）：doc-parser 服务支持（SUPPORTED_EXTENSIONS 含 .doc，走 antiword 提取链路，失败自动回退 LibreOffice 转 docx），可正常提取；提取出的表格为文本形态，复杂表格注意核对错位
- 提取异常（表格错位、缺行、编码乱码）时：报告中注明提取局限，提示人工复核原表对应部分
- 保留原文：数字、单位、位号、术语不得擅自改写；引用必须逐字

### 第三步：结构理解
- 提取目录/章节标题，建立「节号 → 位置」索引
- 汇总全部标识符（设备位号、编号、代码）作为比对主键，形成跨文档标识符全集

### 第四步：五维交叉比对
| 维度 | 检查内容 | 典型发现示例 |
|---|---|---|
| ① 标识符存在性 | 编号一致；「正文有、一览表无」；归属矛盾 | 正文描述的地坑未列入一览表；同一坑被归入两个厂房 |
| ② 参数数值 | 容积/尺寸/标高/流量/压力/浓度限值等 | 全容积 0.2 vs 0.24 m³；氧含量限值 5% vs 3.5% |
| ③ 清单范围 | 成组清单成员多/漏 | 再注入坑清单 8 个 vs 14 个 |
| ④ 术语与技术状态 | 术语统一；技术决策同步 | 一方「不采用 LBB」，另一方仍保留 LBB 描述 |
| ⑤ 分级覆盖 | 安全等级/抗震类别覆盖一致 | 一方有 SC-3 的某管道，另一方未提 |
| ⑥ 一览表完整性 | 正文位号在每张一览表均有条目且参数一致；每张表给出核对结论 | 正文有 901/902/903PS，T-4.2 表无条目；正文标高 -4.00m 与表 -5.95m 差 1.95m |

> ⑥ 必须执行：不得因部分表提取失败而跳过表类核对——提取失败的表要明确列出未核对范围。此为实测补强（2026-08-12 Agent 实测曾漏掉全部「正文有、一览表无」类高严重度项）。

注意基准差异：表压/绝压、全容积/有效容积、底标高/管嘴标高/房间标高——基准不同不一定是错误，标注「需核实」。

### 第五步：严重度分级与出处引用
- **🔴 高**：位号/参数直接冲突、存在性矛盾（正文与表互斥、归属矛盾）
- **🟡 中**：清单范围差异、技术状态不同步、术语/名称混用致歧义、覆盖范围差异
- **🟢 低**：基准含义不明、命名歧义、格式细节、疑似笔误
- 每条必带出处：文档名 + 章节号/表号 + 原文片段；未确证项标注「需核实」

### 第六步：报告输出
按下方模板生成（用户要求导出时用 `write_report`，md/docx/xlsx 按指定格式）。

## 报告模板（输出结构）

```markdown
# {系统/对象} 文件不一致对照审查报告

| 项目 | 内容 |
|---|---|
| 审查日期 | YYYY-MM-DD |
| 审查对象 | {文件 A（版本）} ↔ {文件 B} ↔ {文件 C} |
| 涉及系统 | {系统名/代号} |
| 审查方法 | 全文提取 + 逐项交叉比对（位号/参数/清单/术语/分级） |

## 一、文档清单与比对范围
| 文档 | 对应内容 | 在比对中的角色 |
（注明未纳入范围的内容，如超出审查对象的表）

## 二、不一致项汇总（按严重程度）

### 🔴 高严重度
#### H1. {标题}（{冲突双方}）
| 出处 | 表述 |
| 文件A 章节 | 原文引用 |
| 文件B 章节 | 原文引用 |
问题：{差异描述}
建议：{处理建议}

### 🟡 中严重度
（同上结构）

### 🟢 低严重度
| 编号 | 问题 | 出处对照 | 说明 |

## 三、已确认一致项清单
（核对过无差异的重点项，注明出处，供设计人员复核免检；未核对的范围也在此列出，如「某表提取失败未核对」）

## 四、其他观察与提取局限说明
（提取不全的表格、需人工复核的项）

## 五、结论与处理建议
（按优先级排序的处理顺序建议）
```

## 红线
1. 绝对禁止编造不存在的差异；没有发现就说没有发现
2. 引用原文必须逐字复制
3. 提取失败/工具不可用如实报告，不假装完成
4. 数据结论基于实际提取内容，不估算、不脑补

## 实战参考
本流程源于 2026-08-12 对 RVD 系统文件（2016XRVDXTS02）与 PSAR 9.3 章、附表 T-9.3 的三方一致性审查（产出 15 项不一致：高 5/中 5/低 5）。范例报告位于：`docs/05-测试与反馈/校审测试反馈/提供测试所需相关文件/4、个别系统文件和PSAR文件人工核查不一致的对照/RVD/RVD系统文件与PSAR不一致对照审查报告.md`（可作输出风格与颗粒度参照）。

2026-08-12 已用 deepseek-v4-flash 实测本流程（产出 17 项，与人工 15 项重合 10 项、双向零幻觉）；实测暴露的两点已并入本流程：① 一览表完整性核对必须执行；② 报告须输出「已确认一致项清单」。对比详情见同目录 `Agent与人工审查质量对比报告.md`。
